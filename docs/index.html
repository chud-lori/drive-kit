Mount NTFS and ext read-write, verify, repair, format, and recover lost data, all with free open-source drivers. Run it as dk.

a quick look

Plug in a drive, see what is there, mount it.

Every command takes a whole disk (disk4) or one partition (disk4s1). Destructive ones ask you to type the identifier back before they run.

# see what is plugged in $ dk list IDENT TYPE LABEL MOUNTED AT disk4s1 ntfs FIELDWORK (not mounted) disk5s2 ext backup (not mounted) # mount the NTFS volume read-write $ dk mount disk4s1 # write to ext4 through a short-lived Linux VM (Apple Silicon) $ dk mount --rw disk5s2 # done? release it before you unplug $ dk unmount

what it does

A full disk toolkit, not just a mounter.

drivekit wraps the free open-source drivers and filesystem tools behind one command, with the unmount, confirmation, and never-overwrite-the-source guards handled for you.

Mount

NTFS is read-write by default. ext reads locally; writing opens a short-lived Linux VM so a real kernel driver does the work.

  • dk mountNTFS read-write (ntfs-3g); ext read-only (ext4fuse), no VM
  • dk mount --rwext read-write via anylinuxfs on Apple Silicon, falling back to fuse2fs
  • dk mount --roread-only session using the native driver
  • dk automount enablemount NTFS drives read-write on plug-in

Maintain

Check and repair before data goes missing.

  • dk checkread-only verify
  • dk repairfull fsck / NTFS journal reset
  • dk labelrename a volume
  • dk formaterase as ntfs/ext/exfat/fat

Recover

Get back deleted files, or image a failing drive first.

  • dk recover scanlist recoverable files
  • dk recover carvedeep scan of a formatted disk
  • dk recover imagesafe ddrescue image

Drive tools

The things you reach for when a disk acts up.

  • dk healthSMART check with a plain is-this-failing verdict
  • dk cloneimage or clone a disk, refusing to write onto the source
  • dk partitionshrink, grow, create, or delete partitions
  • dk benchmarksequential read and write speed

on linux too

On Linux it is the repair and recovery toolkit.

Linux already mounts ext, NTFS, and exFAT natively, so there is nothing to add there. drivekit brings the rest: the same check, repair, label, format, info, health, clone, partition, and recover commands, with the same safe-unmount and confirmation guards.

# device names are the Linux ones; a leading /dev/ is fine $ dk doctor # reports the toolkit binaries $ dk setup # installs via apt / dnf / pacman / zypper $ dk repair /dev/sdb1 # fsck after a safe unmount $ dk health sdb

Mounting on Linux stays native, so dk mount / unmount / automount are macOS-only and tell you so.

get it running

Install

Clone the repository and run the installer. It links dk onto your PATH and installs the stack for your platform.

macOS

$ git clone https://github.com/chud-lori/drive-kit $ cd drive-kit $ ./install.sh

Needs Homebrew. Installs macFUSE, ntfs-3g, ext4fuse, and e2fsprogs; anylinuxfs is added on Apple Silicon for ext writes.

Linux

$ git clone https://github.com/chud-lori/drive-kit $ cd drive-kit $ ./install.sh

Uses your package manager to install e2fsprogs, ntfs-3g, exfatprogs, dosfstools, util-linux, gptfdisk, smartmontools, and ddrescue.

Writing ext on macOS runs a small Linux VM (anylinuxfs, Apple Silicon only) that uses about 256 MB of RAM while a write session is open, and shows the volume as a network drive. The first run downloads a Linux image once.

Destructive commands (format, partition, clone to a disk) erase data and ask you to type the target identifier before running.
